# 11월 26일 사업보고서 XML 청킹 v3 작업

## 1. 작업 목적

기존 XML 파이프라인은 요청 기준에 맞는 감사보고서의 재무제표와 주석을 중심으로 문서를 만들고, 사업보고서 본문의 일부 절만 추가한다. 이 때문에 원본 ZIP에 사업보고서 본문이 있더라도 사업 내용, 경영진 분석, 위험 요인 등을 충분히 검색 대상으로 준비하지 못할 수 있다.

v3는 **사업보고서 본문을 더 넓게 추출하고, 연결 또는 별도 기준의 감사보고서 재무제표·주석과 함께 청킹**하기 위한 실험이다. 기존 v2 결과와 분리해 추출 범위와 검색 결과를 비교할 수 있게 한다. v3라는 이름은 청킹 알고리즘이 완전히 새로워졌다는 뜻이 아니다. 현재 청킹은 v2 함수를 재사용하며, 주된 변화는 문서 추출 범위다.

## 2. 처리 흐름과 원본 선택

```text
기업명·사업연도·연결/별도 입력
 → OpenDART 기업 및 사업보고서 접수번호 확인
 → ZIP이 있으면 재사용, 없으면 다운로드
 → 사업보고서 본문 XML + 기준에 맞는 감사보고서 XML 식별
 → 문단·표 등 문서 추출 및 출처 기록
 → v2 분할기를 이용해 v3 청크 생성
 → 선택에 따라 질문 초안 생성 또는 검색 평가
```

ZIP 안의 `<DOCUMENT-NAME>`을 읽어 문서를 선택한다. 파일번호만으로 판단하지 않는다. 확인한 삼성전자 ZIP은 다음과 같다.

| 문서 | 삼성전자 예시 파일 | 사용 내용 |
|---|---|---|
| 사업보고서 본문 | `20260310002820.xml` | 본문의 `P`, `TABLE`, `COVER-TITLE` 텍스트 |
| 연결감사보고서 | `20260310002820_00761.xml` | 연결 기준 재무제표·주석 |
| 감사보고서 | `20260310002820_00760.xml` | 별도 기준 재무제표·주석 |

연결 요청은 본문과 연결감사보고서를, 별도 요청은 본문과 감사보고서를 사용한다. 감사보고서가 없으면 기존 추출 함수가 사업보고서의 해당 기준 재무제표·주석을 대체 원본으로 사용할 수 있다. 사업보고서 본문 XML을 찾거나 읽지 못하면 v3는 중단한다. 본문 재무제표·주석과 감사보고서의 내용은 중복될 수 있다.

원본 XML은 수정하지 않는다. 파싱에 필요한 문자 정리는 메모리에서 수행하고 횟수를 결과에 기록한다. 표와 문단 텍스트를 추출하지만, 이미지·기타 표현과 본문 전체의 누락 여부는 아직 확인해야 한다.

## 3. 변경한 파일과 메타데이터

| 파일 | 역할 |
|---|---|
| `src/fin_research/ingestion/xml_documents_v3.py` | 본문 문단·표와 기존 감사보고서 재무제표·주석을 문서로 생성 |
| `scripts/processing/build_xml_chunks_v3.py` | v2 청킹 함수를 재사용하는 v3 진입점 |
| `scripts/pipelines/run_pipeline_xml_v3.py` | 수집·문서화·청킹, 선택적인 질문 초안 및 평가 실행 |
| `tests/ingestion/test_xml_documents_v3.py` | 본문·감사보고서 선택과 출처 보존 테스트 |
| `tests/pipelines/test_xml_v3_modes.py` | 준비·초안·평가 실행 경로 테스트 |

문서와 청크에는 `source_file`, `source_xpath`, `section`, `title`, `document_type`, `source_document_type` 등 원본 위치와 문서 종류를 남긴다. `statement_scope`는 이번 실행의 연결·별도 기준이다. 별도 `content_scope`는 본문 제목으로 연결·별도를 판별한 경우에만 해당 값을 기록하고, 판별하지 못하면 `unknown`으로 남긴다. **`unknown`은 공통 내용이라고 확정한 값이 아니다.** 이 메타데이터만으로 검색 단계의 기준 구분이 자동 적용되지는 않는다.



## 4. 데이터 수집부터 청킹까지만 실행

```bash
python scripts/pipelines/run_pipeline_xml_v3.py \
  --company 삼성전자 \
  --fiscal-year 2025 \
  --statement-scope consolidated \
  --prepare-only
```

`consolidated`는 연결, `separate`는 별도다. 기존 ZIP이 있으면 재사용한다. 기업명 조회 결과와 원본에 따라 실제 접수번호와 문서·청크 수는 달라질 수 있다. `--prepare-only`는 **평가 질문 생성, Chroma 색인, 검색 평가를 실행하지 않는다.**

위에서 확인한 삼성전자 접수번호 기준 산출물은 다음과 같다.

```text
data/raw/dart/00126380/2025/20260310002820.zip
data/processed/xml/dart/00126380/2025/consolidated/
  20260310002820_xml_documents_v3.json
  20260310002820_xml_chunks_v3.json
  20260310002820_xml_pipeline_v3.json
```

문서 JSON은 추출된 텍스트와 출처, 청크 JSON은 분할된 검색 입력, 파이프라인 JSON은 원본과 건수·설정 기록이다. 기존 v3 결과가 있으면 `--prepare-only`는 덮어쓰지 않고 종료한다. **재생성이 필요한 경우에만** 명령 끝에 `--overwrite`를 붙인다. `--overwrite`는 해당 실행에서 만드는 v3 산출물을 덮어쓰므로 기존 결과를 먼저 보존한다.

기존 ZIP을 직접 지정할 때는 `--zip-path /경로/파일.zip`을 추가할 수 있다. 기업명·고유번호·접수번호를 모두 직접 지정하면 스크립트가 세 값의 일치 여부를 자동 검증하지 않으므로 ZIP과 식별자가 같은 공시인지 확인해야 한다.

## 5. 실제 확인 결과: 삼성전자 2025년 연결

접수번호 `20260310002820`으로 생성된 `xml_pipeline_v3.json`을 확인했다.

| 항목 | 결과 |
|---|---:|
| 사업보고서 본문 문서 | 1,898개 |
| 연결감사보고서 재무제표·주석 문서 | 39개 (재무제표 5, 주석 34) |
| 전체 문서 | 1,937개 |
| 청크 | 3,393개 |
| 청크 크기 / 겹침 설정 | 600 / 100 |

생성된 청크 중 사업보고서 본문 `IV. 이사의 경영진단 및 분석의견` 아래 87개, `V. 회계감사인의 감사의견 등` 아래 55개가 확인됐다. 이 숫자는 **해당 목차 아래 청크 수**이지 해당 내용의 완전성이나 검색 품질을 보증하는 수치가 아니다.

파이프라인 JSON의 `audit.research_coverage`는 기존 추출 함수가 발견한 문맥 항목 수다. v3의 감사보고서 결과에는 재무제표와 주석만 포함하므로, 그 수치가 `audit_documents`에 추가로 포함됐다는 의미는 아니다. 본문의 관련 내용은 별도로 추출된다.


## 6. 확인한 내용과 후속 작업

- 삼성전자 문서·청크 수와 관련 목차 청크 존재를 실제 산출물에서 확인했다. 마녀공장 원본 ZIP 한 건으로 연결·별도 감사보고서 선택과 v3 생성도 확인했다.
- 관련 단위 테스트 14개가 통과했다. 질문 생성과 평가 모드는 외부 호출을 대체한 테스트로 확인했으며, **실제 OpenDART 계정 조회와 임베딩을 포함한 v3 평가 전체 실행은 아직 확인하지 않았다.**
- 사업보고서 XML 목차와 v3 추출 결과를 여러 기업에서 대조하고, 표의 제목·단위·열과 이미지 등 누락 여부를 확인한다.
- `content_scope` 판별과 `unknown` 처리를 보완하고, 연결 요청에 별도 재무정보가 섞이지 않도록 검색 단계에서 실제로 필터·우선순위를 구현하고 검증한다. 현재 v3 준비만으로는 적용되지 않는다.
- 같은 접수번호와 동일한 검증 질문으로 v2·v3를 평가해 기존 재무 검색 결과가 유지되는지 확인한다. 본문과 감사보고서가 겹칠 때 검색 결과와 정답 출처 처리도 검토한다.
- 사업 내용·위험·경영진 분석 질문을 별도 평가셋으로 설계하고 사람이 원문·XPath를 검증한다. 기존 재무 질문과 본문 질문 결과는 구분해 분석한다.
- v3 색인 선택을 API·기존 적재 기업·미적재 기업에 연결하는 작업은 아직 하지 않았다. 검색 품질과 임베딩 비용을 확인한 뒤 적용 범위를 결정한다.
