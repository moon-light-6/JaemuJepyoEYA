# 11월 25일 기업 자동 조회 작업 정리

## 작업 목적과 범위

미적재 기업(30개 선정 기업외의 기업들)도 기업명이나 OpenDART 고유번호로 식별하고, 해당 사업보고서를 찾아 XML 문서와 청크를 준비할 수 있도록 기존 XML v2 파이프라인의 입력·조회 흐름을 정리했다.



## 완료된 작업

- 기업명, 6자리 종목코드 또는 8자리 OpenDART 고유번호로 기업을 찾는다. `--corp-code`만 지정해도 사업보고서 접수번호를 조회할 수 있다.
- 기업명으로 조회한 후보가 없으면 안내하고, 한 개면 선택한다. 이름이 정확히 일치하는 후보가 없으면 이름을 정규화해 다시 찾는다.
- 동명 기업이 여러 개면 고유번호, 종목코드, 대표자, 업종 중분류와 업종코드를 표시한다. 사용자는 `1`, `2`처럼 후보 번호를 입력하며, 잘못 입력하면 다시 선택할 수 있다. Enter는 선택 취소다.
- 기업개황 API가 제공하는 업종코드를 별도 분류표로 변환해 **업종 중분류명**을 보여준다. 분류를 찾을 수 없으면 `확인 불가`로 표시한다.
- 요청한 사업연도의 사업보고서를 다음 해 1월 1일부터 12월 31일까지 조회한다. 정정공시가 여러 개면 기본적으로 최신 접수본을 고른다. 후보가 없으면 기업명·고유번호·사업연도·조회 범위와 함께 아직 공시되지 않았을 가능성을 안내한다.
- 새 기업을 `configs/companies.yaml`에 자동으로 추가하지 않는다. 기업 고유번호와 접수번호를 직접 지정한 경우에도 XML 문서 생성에 필요한 기업명을 OpenDART에서 찾을 수 있다.
- 필요한 XML 문서나 원본 ZIP이 없으면 기존 파이프라인이 ZIP을 수집하고 XML 문서 및 v2 청크를 생성한다.

주요 코드: `scripts/pipelines/run_pipeline_xml_v2.py`, `src/fin_research/ingestion/industry_codes.py`.


## 터미널 명령어

### 1. 기업명으로 실행

삼성전자 2025년 연결재무제표 예시:

```bash
venv/bin/python scripts/pipelines/run_pipeline_xml_v2.py \
  --company "삼성전자" \
  --fiscal-year 2025 \
  --statement-scope consolidated \
  --make-draft-dataset
```

동명 기업 선택 흐름을 확인하려면 기업명을 `비에스엠`으로 바꾸고 출력된 후보 번호를 입력한다. 선택한 기업의 사업보고서가 조회되지 않으면 이후 수집 단계로 진행하지 않는다. 실제로 윤경성 대표의 비에스엠을 2025년으로 선택했을 때 2026년 공시 목록에서 사업보고서를 찾지 못했다.(DART에서 확인했을 때 사업보고서가 아예 없음)

### 2. 고유번호로 실행

기업을 정확히 알고 있거나 대화형 선택 없이 실행할 때 사용한다.

```bash
venv/bin/python scripts/pipelines/run_pipeline_xml_v2.py \
  --corp-code 00126380 \
  --fiscal-year 2025 \
  --statement-scope consolidated \
  --make-draft-dataset
```

별도재무제표가 필요하면 `consolidated` 대신 `separate`를 사용한다. 기업별로 해당 범위의 재무제표가 제공되어야 한다. OpenDART 기업 고유번호 목록을 새로 받으려면 `--refresh-corp-codes`를 추가한다.

### 3. 사업보고서 미조회 안내 확인

2026년 삼성전자 사업보고서는 2027년 공시 목록에서 조회한다. 아직 공시되지 않은 시점이라면 미조회 안내가 나온다.

```bash
venv/bin/python scripts/pipelines/run_pipeline_xml_v2.py \
  --company "삼성전자" \
  --fiscal-year 2026 \
  --statement-scope consolidated \
  --make-draft-dataset
```

## 실행 결과와 현재 한계

`--make-draft-dataset`은 기존 기능으로 draft 평가셋을 생성한 뒤 종료한다. 기존 평가셋이 있으면 덮어쓰지 않는다. 생성되는 경로는 다음과 같다.

```text
data/raw/dart/{corp_code}/{fiscal_year}/{rcept_no}.zip
data/processed/xml/dart/{corp_code}/{fiscal_year}/{scope}/{rcept_no}_xml_documents.json
data/processed/xml/dart/{corp_code}/{fiscal_year}/{scope}/{rcept_no}_xml_chunks_v2.json
evaluation/dataset/xml/{corp_code}/{fiscal_year}/{scope}/{rcept_no}_retrieval.json
```

생성된 문항은 `draft` 상태이며 사람의 검토가 필요하다. **현재 검색 평가는 `verified` 문항만 사용한다.** draft 평가 허용 및 자동 평가 연결은 이번 작업에 포함하지 않았다. 기존 평가를 실행하면 Chroma 인덱스는 기본적으로 `data/chroma_xml_v2/`에 영구 저장된다. draft 생성 명령 자체는 검색 평가 단계까지 실행하지 않는다.

## 확인한 내용

- 동명 기업 후보 번호 선택, 잘못된 번호 재입력, 기업 미존재 및 사업보고서 미조회 안내를 단위 테스트로 확인했다.
- 실제 OpenDART 조회로 비에스엠의 동명 기업 선택과 사업보고서 미조회 사례를 확인했다.
- 파이프라인 테스트: 21개 실행, 19개 통과, 2개 건너뜀. 실제 신규 기업의 전체 XML 수집부터 draft 생성까지는 이번 테스트에서 검증하지 않았다.
