# S# 근거 레지스트리 작업 및 검증 안내

## 목표

XML 검색 청크를 보고서에서 인용할 수 있도록, 보고서 실행 안에서 사용할 짧은 출처 번호 `S1`, `S2`를 발급한다.

같은 원본 XML 파일의 같은 청크를 다시 등록하면 새 번호를 만들지 않고 기존 번호를 반환한다. 서로 다른 청크는 같은 XPath를 가졌더라도 서로 다른 번호를 유지한다.

## 이번 작업 범위

| 파일 | 역할 |
|---|---|
| `src/fin_research/evidence/models.py` | 근거 한 건의 데이터 형식을 정의한다. |
| `src/fin_research/evidence/registry.py` | S# 발급, 중복 제거, 번호 조회를 처리한다. |
| `scripts/check_evidence_registry.py` | 기업별 XML v2 청크로 동작을 검증한다. |

레지스트리는 XML 청크 JSON을 수정하거나, 새 JSON 파일에 S#를 저장하지 않는다. 실행 중인 메모리에서만 출처 목록을 관리한다.

## S# 발급 규칙

중복 여부는 `source_file`과 `chunk_id`를 함께 비교한다.

| 등록 순서 | 입력 청크 | 반환값 |
|---|---|---|
| 1 | 손익계산서 청크 A | `S1` |
| 2 | 같은 손익계산서 청크 A | `S1` |
| 3 | 현금흐름표 청크 B | `S2` |

`S1`을 조회하면 아래 정보가 나온다.

- 원본 XML 파일명
- 원본 XML 위치인 `source_xpath`
- 검색 청크 ID인 `chunk_id`
- 인용 근거가 된 청크 원문인 `text`

## 기업별 검증 방법

프로젝트 루트에서 가상환경을 활성화한 뒤 기업 코드로 실행한다.

```zsh
python scripts/check_evidence_registry.py --corp-code 00260930
```

청크별 S#와 XPath까지 직접 보고 싶으면 `--verbose`를 붙인다.

```zsh
python scripts/check_evidence_registry.py --corp-code 00260930 --verbose
```

검사 대상 기업의 XML v2 청크 파일이 먼저 있어야 한다.

```text
data/processed/xml/dart/기업코드/사업연도/연결기준/*_xml_chunks_v2.json
```

## 성공 결과 읽기

에스엠 예시의 핵심 출력은 아래와 같다.

```text
✅ 검증 성공
1. 279개 청크에 S1~S279 번호를 순서대로 발급했습니다.
2. 279개 청크를 다시 등록해도 처음 받은 S#가 유지됐습니다.
3. 279개 S#를 조회했을 때 XML 파일·XPath·청크 ID·원문이 모두 일치했습니다.
4. 같은 XPath에서 나뉜 청크 38개 그룹도 서로 다른 S#로 유지됐습니다.
```

이 결과는 각 청크를 검증 과정에서 한 번씩 등록해 본 결과다. 실제 보고서에서는 검색과 답변에 사용한 청크만 등록하므로, 보고서에 붙는 S# 개수는 청크 전체 개수보다 적을 수 있다.

## 팀 검증 체크리스트

기업 하나를 맡은 팀원은 아래 순서로 진행한다.

1. 해당 기업의 XML v2 청크 파일이 있는지 확인한다.
2. `--corp-code` 명령을 실행한다.
3. `✅ 검증 성공`과 마지막 `결론` 문장을 확인한다.
4. 오류가 나면 기업 코드, 청크 파일 경로, 오류 전문을 공유한다.
