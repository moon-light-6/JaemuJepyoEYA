# `eval_retrieval.json`에 대하여
이 파일은 삼성전자 사업보고서 검색기가 **질문에 맞는 근거 PDF 페이지를 잘 찾는지** 확인하기 위한 문제지다.

예를 들어 사용자가 “2025년 연결 기준 매출액은 얼마인가?”라고 물었을 때, 검색기가 답과 관련된 청크를 찾고 PDF 85쪽을 근거로 보여 주는지 확인한다. 검색 결과에 정답 페이지가 상위 3개 또는 5개 안에 있으면 검색 성공으로 본다.

이 파일은 답변을 예쁘게 만드는 용도가 아니다. BM25, Vector, MMR, Hybrid-RRF처럼 서로 다른 검색 방식이 **근거 페이지를 얼마나 잘 찾는지** 비교하는 기준이다.

## 지금 들어 있는 문서 범위

- 기업: 삼성전자
- 사업연도: 2025년
- 기준: 연결재무제표
- 원본 파일: `20260310002820.pdf`
- 검색 범위: PDF 물리 페이지 83~195
  - 83~90쪽: 연결재무제표
  - 91~195쪽: 연결재무제표 주석

여기서 쓰는 페이지 번호는 PDF 파일 기준의 **물리 페이지 번호**다. 문서 화면 하단에 인쇄된 `Page 81` 같은 번호와 다를 수 있다. 검색 데이터의 `pdf_page`와 비교할 때는 항상 이 물리 페이지 번호를 쓴다.

## 파일을 열면 이렇게 생겼다

`eval_retrieval.json`은 질문 20개가 들어 있는 JSON 배열이다. 객체 하나가 평가 질문 하나다.

```json
{
  "id": "S04",
  "question": "2025년 연결 기준 매출액은 얼마인가?",
  "answer_type": "numeric",
  "expected_value": "333,605,938",
  "unit": "백만원",
  "gold_sources": [
    {
      "source_file": "20260310002820.pdf",
      "pdf_page": 85
    }
  ],
  "category": "income_statement",
  "annotation_status": "verified"
}
```

이 질문의 뜻은 아래와 같다.

```text
질문: 2025년 연결 기준 매출액은 얼마인가?
정답: 333,605,938백만원
정답 근거: 20260310002820.pdf의 물리 85쪽
```

검색기가 85쪽 청크를 상위 결과에서 찾으면 이 질문은 통과다.

## 각 필드는 이렇게 보면 된다

| 필드 | 쉬운 설명 |
| --- | --- |
| `id` | 질문의 고유 번호. 예: `S04` |
| `question` | 검색기에 실제로 넣어 볼 질문 |
| `answer_type` | 질문이 숫자형인지, 비교형인지, 주석 설명형인지 구분 |
| `expected_value` | PDF를 직접 보고 확인한 정답 |
| `unit` | 숫자 답의 단위. 현재 금액 질문은 `백만원` |
| `gold_sources` | 이 질문의 정답 근거가 있는 PDF 파일과 물리 페이지 번호 |
| `category` | 나중에 어떤 유형에서 검색이 약한지 보기 위한 분류 |
| `annotation_status` | 사람이 PDF 원문을 확인했는지 나타내는 상태 |

### `answer_type`

현재 파일에는 네 유형이 있다.

| 값 | 의미 | 예시 |
| --- | --- | --- |
| `numeric` | 숫자 하나를 찾는 질문 | “연결 기준 영업이익은 얼마인가?” |
| `comparison` | 두 연도나 두 값을 비교하는 질문 | “2025년과 2024년 매출액은 각각 얼마인가?” |
| `note_detail` | 특정 주석의 항목·기준을 찾는 질문 | “매출채권 및 미수금은 몇 번 주석인가?” |
| `narrative` | PDF에 서술된 내용을 찾는 질문 | “파생상품 계약은 어떻게 회계처리하는가?” |

### `gold_sources`

`gold_sources`는 이 평가셋에서 가장 중요한 정보다. 검색 결과가 이 목록의 페이지 중 하나를 찾으면 정답을 찾은 것으로 본다.

답이 한 페이지에 있으면 한 개만 적는다.

```json
"gold_sources": [
  {"source_file": "20260310002820.pdf", "pdf_page": 85}
]
```

답이 표의 앞뒤 페이지에 걸쳐 있거나, 같은 답을 두 페이지가 직접 보여 주면 여러 개를 적는다.

```json
"gold_sources": [
  {"source_file": "20260310002820.pdf", "pdf_page": 129},
  {"source_file": "20260310002820.pdf", "pdf_page": 130}
]
```

이 경우 검색 결과에 129쪽 또는 130쪽이 나오면 해당 질문은 성공이다.

### `annotation_status`

- `draft`: 질문이나 후보 페이지는 만들었지만, PDF 화면에서 아직 최종 확인하지 않은 상태
- `verified`: 질문의 답과 Gold page를 PDF 원문으로 직접 확인한 상태

평가할 때는 `verified`인 항목만 사용하는 것이 안전하다. 현재 20개 항목은 모두 PDF 원문을 확인한 상태다.

## 이 파일은 어떻게 쓰이나?

```text
eval_retrieval.json의 질문 하나 선택
→ BM25 또는 Vector 검색기에 질문 입력
→ 검색 결과의 pdf_page 확인
→ gold_sources 안에 같은 페이지가 있는지 비교
→ 있으면 Hit, 없으면 Miss
```

예를 들어 S04의 Gold page는 85쪽이다.

```text
검색 결과 상위 3개: [85, 113, 83]  → Hit@3 성공
검색 결과 상위 3개: [83, 84, 113]  → Hit@3 실패
```

20개 질문을 모두 실행하면 BM25, Vector, MMR, Hybrid-RRF의 Hit@3·Hit@5를 비교할 수 있다.

## 새 질문을 추가할 때

새 질문을 만들 때는 검색 결과부터 보지 말고, 먼저 PDF 원문을 보고 답과 근거 페이지를 정한다.

1. 현재 검색 범위인 83~195쪽에서 질문 하나를 고른다.
2. PDF 화면에서 답이 직접 보이는 페이지를 찾는다.
3. `expected_value`에 숫자나 핵심 문장을 기록한다.
4. 금액이면 `unit: "백만원"`을 함께 적는다.
5. `gold_sources`에 PDF 물리 페이지 번호를 기록한다.
6. PDF로 확인이 끝나면 `annotation_status`를 `verified`로 둔다.

주의할 점은 두 가지다.

- PDF 하단의 내부 인쇄 페이지 번호가 아니라 PDF 파일의 물리 페이지 번호를 쓴다.
- 제목이나 목차만 있는 페이지가 아니라, 답을 직접 보여 주는 표·문장이 있는 페이지를 Gold page로 쓴다.

## 현재 평가셋 구성

총 20문제이며, 한쪽 유형에만 치우치지 않도록 아래처럼 구성했다.

| 유형 | 개수 |
| --- | ---: |
| 정확한 수치 | 8 |
| 기간 비교 | 4 |
| 주석 세부 | 4 |
| 서술형 근거 | 4 |

이 구성을 유지하면 계정과목·숫자 검색뿐 아니라 주석의 자연어 설명을 찾는 성능도 함께 확인할 수 있다.
